# How to use this system

This folder runs a LaTeX-first application pipeline. In a new chat, send either a job posting link or the pasted posting text. You can add a short note such as `apply as Machine Learning Engineer`, `add German`, or `they use GCP and Airflow`.

## What I produce every time

A new folder: `<YYYY>/<Company>/YYYY-MM-DD - <Role>/` containing:

1. `<file_prefix> - CV.tex` + `.pdf`.
2. `<file_prefix> - Cover Letter.tex` + `.pdf`.
3. The saved job posting as one `.html` file.
4. `<file_prefix> - Interview Prep.md`.

`<file_prefix>` is the filename stem from `identity.toml` `[person].file_prefix`.

German is opt-in. Say `add German` (or `EN+DE`) and I also produce `<file_prefix> - Lebenslauf.tex` + `.pdf` and `<file_prefix> - Anschreiben.tex` + `.pdf`.

DOCX is not generated by default. If a portal specifically requires DOCX, handle it as a separate export request instead of slowing down the normal application pipeline.

## What happens under the hood

1. Archive the posting and create the dated role folder.
2. Match the candidate's real experience to the posting with an honest gap analysis.
3. Research the company and hiring contact.
4. Draft structured English CV and cover-letter payloads.
5. Verify those payloads for factual integrity, relevance, and layout risk.
6. Localise the verified payloads into German (only if German was requested).
7. Write private interview prep as Markdown.
8. Render locked LaTeX templates from `master/LaTeX/templates/`.
9. Compile PDFs and run deterministic PDF/LaTeX health checks.
10. Proofread and final-QA the finished PDFs/text.

## Local prerequisite

PDF compilation needs `latexmk` or `xelatex` available to the shell. Check with:

```bash
python scripts/check_latex_toolchain.py
```

If it fails, install MiKTeX or TeX Live and add the TeX `bin` folder to PATH. If TeX is installed in a custom location, set `LATEX_ENGINE` to the full path of `xelatex.exe` or `latexmk.exe` before rendering. MiKTeX's `latexmk` can require Perl; `xelatex` alone is enough for this pipeline.

Recommended Windows choices:

- MiKTeX: add `C:\Program Files\MiKTeX\miktex\bin\x64` to PATH.
- TeX Live: add `C:\texlive\2026\bin\windows` to PATH.

## Posting Capture and SingleFile

- Browser MCP is not part of the active workflow.
- The capture order is: pasted posting text, static/web fetch, then `scripts/save_singlefile.sh`.
- If automated capture fails and no posting text was pasted, I will ask for the posting text or a manual SingleFile capture instead of trying browser automation.

## The rules I follow

- Strict honesty: every claim comes from `rules/00-canonical-profile.md` or `/master`.
- No invented percentages, unsupported skills, inflated titles, or visa/sponsorship language.
- English only by default; German is added only when you ask for it.
- Primary application files are always `.tex + .pdf`.
- Older `Targeted`, `Non Targeted`, and `2025` folders are style/reference only, never fact sources.

## Model routing

Each subagent pins its own Anthropic model in `.claude/agents/<agent>.md`, tiered by effort:

- Opus — the two generative writing steps only: CV writer and cover-letter writer.
- Sonnet — job matching, company research, verification, German localization, interview prep, proofreading, final QA, LaTeX/script maintenance.
- Haiku — posting capture and folder scaffolding.
- Rendering and healthcheck: local scripts, no model tokens.
- Run the main/orchestrator model on Sonnet (not Opus) — it only coordinates the run.

There is no cross-provider routing or fallback runner in Claude Code / Cowork; the Task tool invokes each subagent with its pinned model directly. Fixed per-agent models make output quality easier to compare and debug.

## Keeping facts current

When career facts change, update `rules/00-canonical-profile.md` or tell me what changed and I will update it. The LaTeX masters control layout, while the canonical profile controls factual claims.

## Folder guide

| Folder | What it is |
|---|---|
| `master/LaTeX/templates/` | Locked LaTeX layouts used for generation. |
| `master/LaTeX/shared/` | Shared LaTeX style/macros/assets references. |
| `master/` | Master assets and legacy DOCX references. |
| `rules/` | Facts, writing voice, German conventions, integrity, and naming rules. |
| `.claude/agents/` | Active specialist-subagent playbooks. |
| `scripts/render_latex_application.py` | Renders structured payloads to `.tex` and PDFs. |
| `scripts/latex_healthcheck.py` | Deterministic pre-QA for `.tex` and PDFs. |
| `scripts/save_singlefile.sh` | Saves a posting URL as one-file HTML when static capture is insufficient. |
| `<YYYY>/<Company>/YYYY-MM-DD - <Role>/` | New application output folders. |
| `2025/`, `Targeted/`, `Non Targeted/` | Past applications/reference only. |
