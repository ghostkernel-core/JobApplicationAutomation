# Folder And Naming Rules

Every application produces one dated role folder containing the full LaTeX/PDF application set. Structure:

```text
<workspace root>/
└── <YYYY>/
    └── <Company>/
        └── YYYY-MM-DD - <Role>/
            ├── <file_prefix> - CV.tex
            ├── <file_prefix> - CV.pdf
            ├── <file_prefix> - Cover Letter.tex
            ├── <file_prefix> - Cover Letter.pdf
            ├── <file_prefix> - Lebenslauf.tex        ┐ only when German
            ├── <file_prefix> - Lebenslauf.pdf        │ was requested for
            ├── <file_prefix> - Anschreiben.tex       │ this run
            ├── <file_prefix> - Anschreiben.pdf       ┘
            ├── <file_prefix> - Interview Prep.tex
            ├── <file_prefix> - Interview Prep.pdf
            └── <posting saved page>.html
```

`<file_prefix>` is the filename stem from `identity.toml` `[person].file_prefix` (git-ignored, one per workspace).

No DOCX files are generated by default.

## Rules

- Company folder: the recognizable company name, cleaned for the filesystem.
- Strip illegal characters: `\ / : * ? " < > |`.
- Keep spaces and `&`.
- Role subfolder: `YYYY-MM-DD - <Role>`, where `<Role>` is the posting title or user's override.
- Year folder: use the year from the role-folder date.
- Documents: the English CV and cover letter as `.tex + .pdf`, the Interview Prep `.tex + .pdf`, and one posting `.html` capture.
- German is opt-in. Add the Lebenslauf and Anschreiben pairs only when the run explicitly asked for German (for example `add German` or `EN+DE`); otherwise produce English only.
- Interview Prep is always English, regardless of whether German was requested.
- Do not include certificates or extra attachments unless explicitly requested.

## Saved posting

Save the SingleFile/static `.html` capture inside the dated role folder. Keep the saved page's descriptive title; if missing, name it `<Company> - <Role>.html`.

## Deriving the company name

Use this priority order:

1. Career-site URL domain.
2. Page `<title>` tag.
3. Posting body `Who we are` / `About us` section.
4. Specific contracting branch/entity only when it is clearly the right application entity.

If two plausible names remain and the cover-letter company name would differ, ask the user.

## Naming consistency

Use `<file_prefix> - <Doc>` for all application documents.

## Do not

- Do not overwrite anything under `/master` or `/rules` — those are the source of truth, not run output.
- Do not place loose company folders or files at the repo root.
- Do not create LaTeX build directories, compiler scratch files, DOCX unpack/edit directories, or temporary artifacts inside the deliverable folder.
- Build in a temp directory and copy only finished `.tex` and `.pdf` files into the dated role folder.
